# QQ音乐浮窗歌词（QQMusicLyrics）

一个自用的 Windows 桌面浮窗歌词程序：读取 QQ 音乐**当前正在播放**的歌曲，联网补全歌词与封面，用一个可完全自定义的置顶透明浮窗显示。目标是替代 QQ 音乐自带的桌面歌词——同样能置顶瞄一眼，但外观和行为都归你自己控制。

---

## 它能做什么

- **只认 QQ 音乐**：浏览器放 B 站/视频产生的媒体会话会被忽略，不会串台显示视频标题
- 自动跟随 QQ 音乐切歌，**单行**显示当前歌词，换句直接切换（不滚动、不显示上下句）
- 浮窗**完全透明、无背景板**、无边框、始终置顶，且**不出现在 Alt+Tab 和任务栏**
- 窗口基础尺寸 **480×116**（WPF 的 DIP）；歌词是**恒定字号**、单行、不换行也不省略，
  一行太长时窗口会**向左右两侧撑开**（始终以原中心展开），所以长句会凸出 480 的框而不是被压缩
- 浮窗歌正上方有一组**细线图标按钮**：锁 · 加号 · 减号（整组居中，加号与锁的间距大于加号与减号的间距）；
  鼠标移入浮窗才淡入，移开 **1 秒**后淡出；加/减调歌词字号，且**只在未锁定状态出现**
- **QQ 音乐没有会话时完全不显示**（暂停不算——暂停时会话还在，歌词停在原处）
- **锁定 = 鼠标穿透**：锁定后浮窗除锁图标外完全不接收鼠标，不挡任何操作；解锁后恢复可拖拽、可右键
- 右键菜单（托盘图标与浮窗右键是**同一套**）：显示 / 隐藏 / 锁定(解锁) / 字号 + / 字号 − / 退出
- **以管理员权限运行**（manifest 里声明 `requireAdministrator`）
- 歌词与封面本地缓存，同一首歌第二次播放不再联网

## 它做不到什么（请先看这条）

- **独占全屏（Exclusive Fullscreen）的游戏里盖不住。** 这是 Windows 的限制，QQ 音乐自带的桌面歌词同样盖不住。把游戏改成"无边框窗口化 / 窗口化"就能正常显示。
- 只能显示 QQ 音乐的内容。其它播放器（包括浏览器视频）一律不显示——这是刻意设计的。
- **锁定之后整窗鼠标穿透**，但**锁图标那一小块会临时取消穿透**：把鼠标移到图标上点一下就能解锁（和 QQ 音乐自带歌词的行为一致）。托盘菜单同样可以解锁。
- 因为要求管理员权限，**每次启动都会弹一次 UAC**；这也意味着"开机自启"如果以后加回来，登录时同样会弹 UAC。
- "歌名 → 歌曲 ID"的匹配不可能 100% 准确，详见下方[已知限制](#已知限制与风险)；也验证过"能否绕开搜索直接拿精确 ID"，结论见[附录](#附能不能不靠搜索直接拿到精确歌曲-id)。

## 工作原理

三层，互不耦合：

| 层 | 职责 | 用到的接口 |
|---|---|---|
| 采集层 | 读"当前在听什么" | Windows SMTC（系统媒体传输控制），`Windows.Media.Control` 命名空间 |
| 补全层 | 歌名 + 歌手 → 歌词 + 封面 | QQ 音乐公开只读 Web 接口 + 本地磁盘缓存 |
| 呈现层 | 画浮窗 | WPF 无边框透明窗口 + 少量 Win32 扩展样式 |

### 为什么叫"低侵入"

采集层只是**向操作系统查询媒体会话**，读到的就是 Windows 音量面板上那张"正在播放"卡片里的信息。它：

- 不注入 QQ 音乐进程、不读写它的内存
- 不 hook 它的网络请求、不修改它的任何文件
- 不需要登录、不接触任何账号数据

### 位置精度是怎么做到的（实测结论）

QQ 音乐每秒通过 SMTC 上报一次时间轴，但上报值是阶梯状量化的（约 0.88 秒一格），直接拿来用歌词会一顿一顿。实测 `LastUpdatedTime` 与系统时钟只差 0.02~0.3 秒，因此程序以它为锚点外推：

```
当前位置 = 上报位置 + (当前时刻 − 上报时刻)
```

从而得到毫秒级的连续位置，逐行切换才是准的。

## 环境要求

- Windows 10 1809（17763）或更高；开发验证于 Windows 11 build 26300
- QQ 音乐 PC 版；开发验证于 21.62
- 构建需要 **.NET 8 SDK**；运行需要 **.NET 8 桌面运行时**

## 构建

```powershell
# 只构建程序本体
dotnet build src\QQMusicLyrics -c Release

# 或构建整个解决方案（含自测工程）
dotnet build QQMusicLyrics.sln -c Release
```

产出在 `src\QQMusicLyrics\bin\Release\net8.0-windows10.0.19041.0\QQMusicLyrics.exe`。

打包成单文件（可选）：

```powershell
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true
```

## 运行

程序清单里声明了 `requireAdministrator`，所以**双击时会弹一次 UAC**，允许后才会启动。也可以用命令行：

```powershell
dotnet run --project src\QQMusicLyrics
```

> 为什么要管理员权限：在部分环境下，非提权进程注册的托盘图标会加不进系统托盘区。

启动后托盘会出现一个音符图标。浮窗本身**只在 QQ 音乐有播放会话时才出现**——如果 QQ 音乐没在放歌（或没启动），屏幕上什么都不会有，这是预期行为。

## 使用

所有操作都在**托盘菜单**里；在浮窗上**点右键**会弹出同一个菜单（这是最省事的入口，不用去翻托盘）。

> **Windows 11 注意**：系统默认会把新出现的托盘图标收进任务栏的 **"显示隐藏的图标"（`^`）** 面板里，所以第一次运行时你在托盘区可能看不到它。点一下 `^` 就能找到，图标名是"QQ音乐浮窗歌词"。想让它常驻可见：**设置 → 个性化 → 任务栏 → 其他系统托盘图标**，把这一项打开。
>
> 懒得找托盘也没关系：**直接在浮窗上点右键**，弹出来的是完全相同的菜单。

菜单项如下，**托盘图标右键和浮窗右键是同一个菜单**：

| 菜单项 | 说明 |
|---|---|
| 显示 | 取消"手动隐藏"，让浮窗重新显示（QQ 音乐没会话时仍然不会显示） |
| 隐藏 | 手动藏起浮窗，直到再次点"显示" |
| 锁定 / 解锁 | 未锁定时显示「锁定」+**开着的锁**；点一下即锁定，文字变「解锁」+**关着的锁**。**锁定 = 同时开启鼠标穿透** |
| 字号 + | 加号图标；歌词字号 +2（与浮窗上的加号按钮同一动作） |
| 字号 − | 减号图标；歌词字号 −2 |
| 退出 | 结束程序 |

### 锁定（= 鼠标穿透）怎么用

1. **未锁定**时浮窗可拖动、可右键；鼠标移进浮窗，歌正上方会出现「锁 · 加 · 减」三个细线按钮（移开 **1 秒**后自动隐藏）。加/减只在未锁定状态出现。
2. 点浮窗上的锁图标、或菜单里的「锁定」，都会进入锁定：浮窗**立刻变成鼠标穿透**，鼠标点击/拖拽全部穿过去，不再挡任何操作。
3. **锁定后整窗穿透**，但**锁图标那一小块例外**：把鼠标移到图标上，那一小块会临时取消穿透（图标也会亮起），点它就能直接解锁；托盘菜单里点「解锁」同样可以。

   > 实现方式：`WS_EX_TRANSPARENT` 是整窗级别的、没法只作用于一部分，所以程序按光标位置**动态切换**这个样式 —— 光标进入锁图标点击区就取消穿透，离开就恢复；判定靠轮询光标（穿透时窗口收不到鼠标事件）。

> 托盘图标在 Windows 11 里默认收在 **"显示隐藏的图标"（`^`）** 里。点 `^` 就能找到；想常驻可见：**设置 → 个性化 → 任务栏 → 其他系统托盘图标**。

## 数据存放位置

运行期数据全部集中在 `%APPDATA%\QQMusicLyrics\`，不污染其他目录：

| 路径 | 内容 |
|---|---|
| `settings.json` | 设置（窗口位置尺寸、字号、各开关、歌词偏移） |
| `cache\lyrics\*.json` | 歌词缓存（按"歌名+歌手"哈希） |
| `cache\covers\*.jpg` | 封面缓存 |
| `log.txt` | 运行日志，**排错先看这里** |

删掉整个 `QQMusicLyrics` 目录 = 恢复出厂状态。

## 附：能不能不靠搜索、直接拿到精确歌曲 ID？

"歌名 → 歌曲 ID"是整条链路里唯一不精确的环节，所以专门验证过"能不能绕开它"。三条路都实测了：

| 路子 | 实测结论 |
|---|---|
| **读本地数据** | ❌ **实测走不通。** 用已知的 8 个真实 songmid + 对应曲名当探针，扫描 `%APPDATA%\Tencent\QQMusic`、QQ 音乐安装目录、`LocalAppData\Tencent`、`SSN` 共约 **477 MB**，**零命中**——腾讯没有把明文歌曲 ID 或曲名落盘。播放时唯一被写入的库是 `qmlist64.db`（20 MB，旁边还有 `-journal`），但它是**加密的自有格式**：头部不是 `SQLite format 3`，Python 的 `sqlite3` 直接报 `file is not a database`。要读它得反它的加密（密钥在 `QQMusic.dll` 里）。注册表里也只有安装配置，没有正在播放的信息。 |
| **抓包** | ⚠️ 理论可行，代价高。客户端除了 HTTPS 还走自有的 WNS 通道（其日志里能看到 `WnsRequestPacker` / `generateRequestData`，而且**只记录长度、不记录内容**，所以日志里也挖不到）。要拿明文必须做 MITM：给系统装自签根证书。风险在于这等于把整机 HTTPS 交托给该证书，且客户端可能做证书校验，接口 body 本身也可能有第二层加密与 `sign` 签名。 |
| **读进程内存** | ⚠️ 最可能成功，但很脆。思路是 `ReadProcessMemory` 扫 `QQMusic.exe`，先定位曲名字符串，再在附近找 14 位 base62 的 token（songmid 的形态），最后用歌词接口验证。现实障碍：客户端带 `VMProtectSDK`，内存布局属于内部实现，**腾讯一升级就可能失效**——会把项目变成追着版本跑的逆向工程，与"低侵入"定位冲突。 |

**更划算的替代方案（尚未实现）**：不匹配问题的真正解法可能根本不需要精确 ID。SMTC 除了歌名/歌手，还能拿到**总时长**和**专辑名**，而这两个信号目前完全没用上——QQ 搜索返回的 `interval`（秒）可以直接和 SMTC 的时长对齐，同名/翻唱候选通常能靠几秒的时长差区分开；再用专辑名做二次打分。这比抓包便宜得多，也不会因腾讯升级而失效。

## 已知限制与风险

1. **独占全屏盖不住**（见上）。
2. **歌名匹配可能偏差。** 实测把"歌名+歌手"一起当关键词搜索反而 0 命中（`半抹烟熏 封茗囧菌` → 0 条；只搜 `半抹烟熏` → 1 条），而且首条命中常常是翻唱版。程序的做法是"只用歌名搜 → 按歌手名打分挑一条 → 把结果缓存下来"，并把**实际匹配到的曲目**显示在托盘悬浮提示里，方便你判断是否匹配错。目前菜单里还没有"重新匹配"入口（等后续加回），需要时删缓存文件即可。
3. **翻译歌词只有部分歌曲有**（取决于 QQ 接口的 `trans` 字段），没有时该行不显示。
4. **暂不支持逐字高亮。** QQ 接口只提供逐行时间轴；逐字是它自有的加密 QRC 格式。当前实现是"单行 + 换句时淡入"。
5. **QQ 接口是非官方的公开 Web 接口**，官方随时可能改动。失效时程序不会崩，只会显示歌名。
6. 若在 QQ 音乐设置里关闭了系统媒体控制，将读不到播放状态。

## 排错

| 现象 | 处理 |
|---|---|
| 浮窗完全不出现 | 正常前提是 QQ 音乐**正在播放**。确认 QQ 音乐在放歌、任务栏音量面板里有它的媒体卡片；再查 `log.txt` |
| 浏览器放视频时也显示了视频标题 | 不应该发生（只认 `QQMusic.exe`）。若真出现，把 `log.txt` 里的 `AUMID` 发我 |
| 浮窗出现但只显示歌名 | 说明歌词没匹配到 |
| 歌词匹配错了 | 目前菜单里还没有"重新匹配"。删掉 `%APPDATA%\QQMusicLyrics\cache\lyrics\` 里对应的 json 再重启，就会重新匹配 |
| **锁定后拖不动、也点不动** | **这是设计如此**：锁定 = 整窗鼠标穿透。把鼠标移到锁图标上点一下，或从托盘菜单点「解锁」即可恢复 |
| 锁定后鼠标移到锁图标上却能点到 | 这是刻意的：图标那一小块会临时取消穿透，好让你在锁定状态下直接解锁 |
| 浮窗上的锁图标看不见 | 它只在鼠标移到浮窗范围内时出现；且浮窗本身在没有 QQ 音乐会话时是隐藏的 |
| 鼠标穿透没有生效 | 确认菜单里显示的是「解锁」（说明当前已锁定）而不是「锁定」 |
| 窗口太小/太大或跑到屏幕外 | 删除 `settings.json`，程序会回到 480×116 与底部居中 |
| 启动没弹 UAC / 托盘没有图标 | 确认是用 `bin\Release\...\QQMusicLyrics.exe` 启动的（清单已内嵌）；托盘图标可能在 `^` 溢出区里 |
| 接口失效想改地址 | 接口集中在 `src/QQMusicLyrics/Net/QQMusicClient.cs` |
| 想确认只认 QQ 音乐 | `dotnet run --project tests\QQMusicLyrics.SelfTest -c Release`，第 2 节会列出所有会话并标注采用/忽略 |

## 开发笔记：实际踩到的坑

这些是开发过程中真实撞到、并已修复的问题，记下来免得以后重踩。

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | 封面永远拿不到 | QQ 音乐通过 SMTC 上报的缩略图是**空流**（`ContentType` 为空、流长度 0），连续三次实测一致 | 封面改走网络：`smartbox` → `albumMid` → `y.gtimg.cn` |
| 2 | 浮窗完全不显示 | `RestorePosition` 把 **物理像素**（WinForms `Screen.WorkingArea`）和 **DIP**（`Window.Left/Top/Width/Height`）混用。在 150% 缩放的屏幕上窗口被算到 `y=1842`，而屏幕只有 1600 高 | 全程改用 DIP 单位的 `SystemParameters.WorkArea` |
| 3 | 同一首歌被解析两遍 | 启动时 `AttachSession` 里"触发即忘"地刷了一次，外层又补触发一次 | `StartAsync` 内改为 `await RefreshAsync()`，外层不再补触发 |
| 4 | 封面固定 15 秒超时后失败 | `y.gtimg.cn` 解析出 9 个地址，其中偶尔有一个 TCP 连接**永久黑洞**；而 `SocketsHttpHandler.ConnectTimeout` 默认是"无限"，于是一直卡到 `HttpClient` 的整体超时、期间不换地址 | 设 `ConnectTimeout = 5s`，并加一次重试 |
| 5 | 歌词抓到了但界面一直卡在"正在匹配歌词…" | `HttpClient` 自身超时抛的是 `TaskCanceledException`（属 `OperationCanceledException`），代码把它当"用户取消"直接 rethrow，上层静默丢弃整首歌 | 改为 `catch (OperationCanceledException) when (token.IsCancellationRequested)` |
| 6 | 歌词上屏被封面拖慢 | 封面下载是 `await` 的，封面慢则歌词也慢 | 封面改为后台任务，永不阻塞歌词 |
| 7 | 搜索命中翻唱版 | 关键词里带歌手名反而 0 命中；关键词只有歌名时首条常是翻唱 | 只用歌名搜 + 按歌手打分 + 结果缓存 |
| 8 | 拖动时窗口只跟着鼠标走一半，拖起来发飘 | 用"鼠标相对窗口的坐标"做位移增量，而窗口自己也在移动，形成反馈回路：`L = L0 + (M−L) − (M0−L0)` → 位移恒为鼠标位移的 1/2 | 改用屏幕坐标（`GetCursorPos` + `TransformFromDevice` 换成 DIP）做增量，与窗口位置无关，位移严格 1:1 |
| 9 | 改成"无会话就隐藏"之后，浮窗再也不出现了（日志显示会话正常、歌词也匹配到了） | 可见性判断用了一个自己维护的 `_isHidden` 缓存标志。构造期（窗口还没 `Show()`）就先算了一次"应该隐藏"并把标志置成 true，之后真实状态与标志失步，再算出来"应该显示"时被当成"状态没变"直接跳过 | 不再用缓存标志，直接比较窗口**真实**的 `Visibility`；并且加 `_ready` 门禁，窗口 `Show()` 之前一律不动可见性；同时订阅 `SessionAvailabilityChanged` 让响应不依赖 30fps 轮询 |
| 10 | 改成 480×116 后，老用户的窗口还是 1000×180 | 设置文件里存着旧值，改代码默认值对它无效 | 给设置加 `SettingsVersion` 与显式迁移（v0→v2 重置尺寸/字号/翻译开关，并让窗口回到"底部居中"） |
| 11 | 窗口位置还没确定时，任何一次"锁定"都会让设置**静默保存失败** | `Left/Top` 用 `double.NaN` 表示"未确定"，而 `System.Text.Json` 无法把 NaN 写成合法 JSON，序列化直接抛异常（被 `Save()` 的 catch 吞掉） | 改用可空 `double?`（null 表示未确定），彻底不出现 NaN |
| 12 | 锁定后整窗穿透，导致锁图标也点不到、没法自己解锁 | `WS_EX_TRANSPARENT` 是**整窗级别**的开关，没有"只让某个区域不穿透"的用法 | 按光标位置**动态切换**：光标进入锁图标点击区 → 取消穿透；离开 → 恢复穿透。判定必须轮询光标（穿透时窗口收不到任何鼠标事件）。点击区比图标大一圈，避免"移过去的一瞬间还没取消穿透" |
| 13 | 长歌词被缩得很小、再长就被省略号截断，读不全 | 固定 480 宽的窗口里，恒定字号放不下就只能缩字或截断 | 改成**窗口跟随文字宽度**：基础宽度 480，长句时左右同时撑开（改 `Left` 保持中心不动）；同时把字号改成恒定、不再逐行缩放，字号只由加减按钮/菜单控制 |
| 14 | 480 基础宽度会被存进设置，重启后位置算错 | 窗口宽度变成动态后，`Left` 不再对应"基础框"的左边界 | `SaveBounds` 存的是 `Left + (窗口宽 - 基础宽)/2`（即基础框左边界）；重启后长句仍围绕同一中心展开 |

另外两个与代码无关但值得记的环境事实：

- 这台机器原本**没有 .NET SDK**（只有运行时），已把 **.NET 8 SDK 8.0.404** 装进 `C:\Program Files\dotnet`（未改 PATH，全局 `dotnet` 直接可用）。
- 官方 `aka.ms` / `builds.dotnet.microsoft.com` 从本机下载只有约 34 KB/s，而 `dotnetcli.azureedge.net` 有约 1.5 MB/s。以后装 SDK 走后者。
- 用 `File.OpenRead`（共享模式 `FileShare.Read`）读 QQ 音乐正在写的文件会报"被另一进程占用"；换成 `FileShare.ReadWrite` 就能读。第一次侦察就是因为这个静默跳过了 `qmlist64.db`。
