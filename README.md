# QQ音乐浮窗歌词（QQMusicLyrics）

一个自用的 Windows 桌面浮窗歌词程序：读取 QQ 音乐**当前正在播放**的歌曲，联网补全歌词与封面，用一个可完全自定义的置顶透明浮窗显示。目标是替代 QQ 音乐自带的桌面歌词——同样能置顶瞄一眼，但外观和行为都归你自己控制。

---

## 它能做什么

- 自动跟随 QQ 音乐切歌，显示逐行歌词（有翻译时可选显示翻译）
- 浮窗无边框、逐像素透明、始终置顶，且**不出现在 Alt+Tab 和任务栏**
- **鼠标穿透**：开启后打游戏时完全不挡鼠标操作
- 拖拽移动、位置记忆、锁定位置
- 托盘常驻（托盘是"永远够得着"的控制入口）
- 播放控制：上一首 / 播放·暂停 / 下一首
- 歌词偏移微调、字号调整、背景板开关、翻译开关、上下行歌词开关
- 可选开机自启（**默认关闭**）
- 歌词与封面本地缓存，同一首歌第二次播放不再联网

## 它做不到什么（请先看这条）

- **独占全屏（Exclusive Fullscreen）的游戏里盖不住。** 这是 Windows 的限制，QQ 音乐自带的桌面歌词同样盖不住。把游戏改成"无边框窗口化 / 窗口化"就能正常显示。
- 只针对 QQ 音乐 PC 版做了歌词匹配（任何向系统上报播放状态的应用都能读到曲目，但歌词补全按 QQ 音乐曲库来）。
- "歌名 → 歌曲 ID"的匹配不可能 100% 准确，详见下方[已知限制](#已知限制与风险)。

## 工作原理

三层，互不耦合：

| 层 | 职责 | 用到的接口 |
|---|---|---|
| 采集层 | 读"当前在听什么" | Windows SMTC（系统媒体传输控制），`Windows.Media.Control` 命名空间 |
| 补全层 | 歌名 + 歌手 → 歌词 + 封面 | QQ 音乐公开只读 Web 接口 + 本地磁盘缓存 |
| 呈现层 | 画浮窗 | WPF 无边框透明窗口 + 少量 Win32 扩展样式 |

### 为什么叫"低侵入"

采集层只是**向操作系统查询媒体会话**，读到的就是 Windows 音量面板上那张"正在播放"卡片里的信息。它：

- 不注入 QQ 音乐进程、不读写它的内存
- 不 hook 它的网络请求、不修改它的任何文件
- 不需要登录、不接触任何账号数据

### 位置精度是怎么做到的（实测结论）

QQ 音乐每秒通过 SMTC 上报一次时间轴，但上报值是阶梯状量化的（约 0.88 秒一格），直接拿来用歌词会一顿一顿。实测 `LastUpdatedTime` 与系统时钟只差 0.02~0.3 秒，因此程序以它为锚点外推：

```
当前位置 = 上报位置 + (当前时刻 − 上报时刻)
```

从而得到毫秒级的连续位置，逐行切换才是准的。

| 能力 | 途径 | 实测结果 |

## 环境要求

- Windows 10 1809（17763）或更高；开发验证于 Windows 11 build 26300
- QQ 音乐 PC 版；开发验证于 21.62
- 构建需要 **.NET 8 SDK**；运行需要 **.NET 8 桌面运行时**

## 构建

```powershell
cd src\QQMusicLyrics
dotnet build -c Release
```

产出在 `src\QQMusicLyrics\bin\Release\net8.0-windows10.0.19041.0\QQMusicLyrics.exe`。

打包成单文件（可选）：

```powershell
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true
```

## 运行

直接双击 `QQMusicLyrics.exe`，或：

```powershell
dotnet run --project src\QQMusicLyrics
```

启动后浮窗默认出现在屏幕底部居中，托盘出现一个音符图标。

## 使用

所有操作都在**托盘菜单**里；在浮窗上**点右键**会弹出同一个菜单（这是最省事的入口，不用去翻托盘）。

> **Windows 11 注意**：系统默认会把新出现的托盘图标收进任务栏的 **"显示隐藏的图标"（`^`）** 面板里，所以第一次运行时你在托盘区可能看不到它。点一下 `^` 就能找到，图标名是"QQ音乐浮窗歌词"。想让它常驻可见：**设置 → 个性化 → 任务栏 → 其他系统托盘图标**，把这一项打开。
>
> 懒得找托盘也没关系：**直接在浮窗上点右键**，弹出来的是完全相同的菜单。

菜单项如下：

| 菜单项 | 说明 |
|---|---|
| 显示浮窗 | 临时隐藏/显示 |
| 鼠标穿透（打游戏不挡操作） | 开启后鼠标事件完全穿过浮窗。**开启时无法拖动窗口**，要先关掉它 |
| 锁定位置 | 禁止拖动 |
| 无播放时自动隐藏 | 没有媒体会话时自动收起 |
| 上一首 / 播放·暂停 / 下一首 | 走系统媒体控制转发给 QQ 音乐 |
| 重新匹配歌词 | 清掉该曲目缓存并重新搜索（匹配错了就用这个） |
| 显示翻译歌词 | 该曲目有翻译时才有效 |
| 显示上下行歌词 | 关掉则只显示当前一行 |
| 显示深色背景板 | 在亮色游戏画面上更易读 |
| 歌词提前 / 延后 100 ms | 微调歌词与声音的同步 |
| 字号 + / − / 重置 | 也可以在浮窗上 `Ctrl + 滚轮` 直接调 |

## 数据存放位置

运行期数据全部集中在 `%APPDATA%\QQMusicLyrics\`，不污染其他目录：

| 路径 | 内容 |
|---|---|
| `settings.json` | 设置（窗口位置尺寸、字号、各开关、歌词偏移） |
| `cache\lyrics\*.json` | 歌词缓存（按"歌名+歌手"哈希） |
| `cache\covers\*.jpg` | 封面缓存 |
| `log.txt` | 运行日志，**排错先看这里** |

删掉整个 `QQMusicLyrics` 目录 = 恢复出厂状态。

## 已知限制与风险

1. **独占全屏盖不住**（见上）。
2. **歌名匹配可能偏差。** 实测把"歌名+歌手"一起当关键词搜索反而 0 命中（`半抹烟熏 封茗囧菌` → 0 条；只搜 `半抹烟熏` → 1 条），而且首条命中常常是翻唱版。程序的做法是"只用歌名搜 → 按歌手名打分挑一条 → 把结果缓存下来"，并把**实际匹配到的曲目**显示在托盘悬浮提示里，方便你判断是否匹配错。匹配错时用"重新匹配歌词"。
3. **翻译歌词只有部分歌曲有**（取决于 QQ 接口的 `trans` 字段），没有时该行不显示。
4. **暂不支持逐字高亮。** QQ 接口只提供逐行时间轴；逐字是它自有的加密 QRC 格式。当前实现是"逐行高亮 + 淡入上移过渡"。
5. **QQ 接口是非官方的公开 Web 接口**，官方随时可能改动。失效时程序不会崩，只会显示"未找到歌词"。
6. 若在 QQ 音乐设置里关闭了系统媒体控制，将读不到播放状态。

## 排错

| 现象 | 处理 |
|---|---|
| 浮窗不出现 | 看托盘图标在不在；查 `log.txt` |
| 一直显示"等待 QQ 音乐播放…" | 确认 QQ 音乐正在播放，且 Windows 音量面板里能看到它的媒体卡片 |
| 歌词匹配错了 | 托盘 → 重新匹配歌词 |
| 歌词比声音快/慢 | 托盘 → 歌词提前 / 延后 100 ms |
| 窗口拖不动 | 先关掉"鼠标穿透"和"锁定位置" |
| 窗口跑到屏幕外 | 删除 `settings.json`，程序会回到默认位置 |
| 接口失效想改地址 | 接口集中在 `src/QQMusicLyrics/Net/QQMusicClient.cs` |

## 开发笔记：实际踩到的坑

这些是开发过程中真实撞到、并已修复的问题，记下来免得以后重踩。

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | 封面永远拿不到 | QQ 音乐通过 SMTC 上报的缩略图是**空流**（`ContentType` 为空、流长度 0），连续三次实测一致 | 封面改走网络：`smartbox` → `albumMid` → `y.gtimg.cn` |
| 2 | 浮窗完全不显示 | `RestorePosition` 把 **物理像素**（WinForms `Screen.WorkingArea`）和 **DIP**（`Window.Left/Top/Width/Height`）混用。在 150% 缩放的屏幕上窗口被算到 `y=1842`，而屏幕只有 1600 高 | 全程改用 DIP 单位的 `SystemParameters.WorkArea` |
| 3 | 同一首歌被解析两遍 | 启动时 `AttachSession` 里"触发即忘"地刷了一次，外层又补触发一次 | `StartAsync` 内改为 `await RefreshAsync()`，外层不再补触发 |
| 4 | 封面固定 15 秒超时后失败 | `y.gtimg.cn` 解析出 9 个地址，其中偶尔有一个 TCP 连接**永久黑洞**；而 `SocketsHttpHandler.ConnectTimeout` 默认是"无限"，于是一直卡到 `HttpClient` 的整体超时、期间不换地址 | 设 `ConnectTimeout = 5s`，并加一次重试 |
| 5 | 歌词抓到了但界面一直卡在"正在匹配歌词…" | `HttpClient` 自身超时抛的是 `TaskCanceledException`（属 `OperationCanceledException`），代码把它当"用户取消"直接 rethrow，上层静默丢弃整首歌 | 改为 `catch (OperationCanceledException) when (token.IsCancellationRequested)` |
| 6 | 歌词上屏被封面拖慢 | 封面下载是 `await` 的，封面慢则歌词也慢 | 封面改为后台任务，永不阻塞歌词 |
| 7 | 搜索命中翻唱版 | 关键词里带歌手名反而 0 命中；关键词只有歌名时首条常是翻唱 | 只用歌名搜 + 按歌手打分 + 结果缓存 |
| 8 | 拖动时窗口只跟着鼠标走一半，拖起来发飘 | 用"鼠标相对窗口的坐标"做位移增量，而窗口自己也在移动，形成反馈回路：`L = L0 + (M−L) − (M0−L0)` → 位移恒为鼠标位移的 1/2 | 改用屏幕坐标（`GetCursorPos` + `TransformFromDevice` 换成 DIP）做增量，与窗口位置无关，位移严格 1:1 |

另外两个与代码无关但值得记的环境事实：

- 这台机器原本**没有 .NET SDK**（只有运行时），已把 **.NET 8 SDK 8.0.404** 装进 `C:\Program Files\dotnet`（未改 PATH，全局 `dotnet` 直接可用）。
- 官方 `aka.ms` / `builds.dotnet.microsoft.com` 从本机下载只有约 34 KB/s，而 `dotnetcli.azureedge.net` 有约 1.5 MB/s。以后装 SDK 走后者。

## 代码结构

```
src/QQMusicLyrics/
├─ App.xaml(.cs)              应用入口：单实例、装配各层、曲目变化 → 歌词解析
├─ Media/SmtcMediaService.cs  采集层：SMTC 会话订阅 + 位置外推 + 播放控制
├─ Lyrics/
│  ├─ LrcParser.cs            LRC 解析，按时间戳合并翻译
│  ├─ MatchScorer.cs          候选打分（歌名变体 + 歌手相似度）
│  ├─ LyricCache.cs           歌词磁盘缓存
│  └─ LyricResolver.cs        补全层编排：缓存 → 搜索 → 详情 → 歌词 → 封面
├─ Net/QQMusicClient.cs       QQ 音乐只读接口客户端（含 Referer 处理）
├─ UI/
│  ├─ LyricsWindow.xaml(.cs)  浮窗：透明置顶、逐行高亮、拖拽、穿透、滚轮调字号
│  ├─ TrayIcon.cs             托盘图标与菜单（图标在运行时绘制）
│  └─ AppCommands.cs          托盘与右键共用的命令集
├─ Interop/
│  ├─ NativeMethods.cs        WS_EX_TRANSPARENT / TOOLWINDOW / NOACTIVATE
│  └─ AutoStart.cs            HKCU Run 键开机自启（可逆）
├─ Settings/AppSettings.cs    设置持久化与越界值修正
└─ Infra/AppPaths.cs          路径规划 + 滚动日志
```
